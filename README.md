# Capibara: командное решение кейса

Здесь собраны материалы хакатона и распределение работы между четырьмя компьютерами. Начните с [КОМАНДА.md](КОМАНДА.md): там задачи, границы ответственности, требования к решению и готовые сообщения для Codex или Claude Code.

В [qa/README.md](qa/README.md) находятся результаты независимого профилирования исходных CSV и описание диагностических проверок. Аудит ещё нужно выполнить в рабочем PostgreSQL и отдельно проверить модель `core`; актуальное распределение этой работы — в плане команды.

## Начало работы

Вы работаете на компьютере 1 и запускаете отдельного помощника на каждом из компьютеров 2–4. Сначала передайте в общий репозиторий актуальные файлы модели, план и папку `qa/`: пока они не опубликованы, другие компьютеры их не получат. Затем на каждом компьютере клонируйте репозиторий и создайте **свою** ветку. Если репозиторий закрыт, для клонирования и отправки веток нужен доступ к нему.

```bash
git clone https://github.com/Shadovv-Government/-.git capibara
cd capibara
```

Затем используйте команду для своего компьютера:

```bash
# Компьютер 2 — ключи, связи, стратегия и ответы
git switch -c team/quality

# Компьютер 3 — аналитика, финансовые сверки и ответы
git switch -c team/analytics

# Компьютер 4 — сохранность данных, дашборд и ответы
git switch -c team/presentation
```

Запустите только одну команду `git switch -c` — соответствующую компьютеру; если ветка уже существует, используйте `git switch` без `-c`. После этого откройте папку `capibara` в Codex или Claude Code и вставьте текст для этого компьютера из [КОМАНДА.md](КОМАНДА.md). Компьютер 1 отвечает за модель и координацию интеграции. Сеансы не обмениваются результатами автоматически: передавайте ветки и отчёты между ними сами.

## Локальная база

При запущенном Docker и доступе к интернету:

```bash
cd project
bash scripts/setup.sh
```

Скрипт организаторов скачивает исходные CSV и загружает их в локальный PostgreSQL. Подробнее об окружении и устранении ошибок — в [project/README.md](project/README.md). Данные из `project/data/` не коммитятся. `--reset` удаляет локальный volume базы проекта — используйте его только когда это действительно нужно.

## Как передать результат

Работайте в своей папке, указанной в плане. Когда работа готова, проверьте `git status` и добавьте через `git add` только файлы своей роли, в том числе новые. Затем сохраните их в своей ветке и отправьте на GitHub:

```bash
git status
git commit -m "Describe your changes"
git push -u origin HEAD
```

Передайте название ветки на компьютер 1 и откройте pull request в `main`, если у вас есть доступ. Не отправляйте секреты или исходные CSV. Если нужные данные или результаты другого компьютера ещё не готовы, выполняйте независимую часть задачи и передайте на компьютер 1 список ожидающих вопросов.

Материалы организаторов скопированы в `project/` из `hackathon-students` на коммите `3da32d1`. Новые вопросы организаторов автоматически здесь не появятся: порядок обновления описан в плане.
