## Как считали

- Файл: [`q5_revenue_by_category.sql`](q5_revenue_by_category.sql), только `core`.
- **Уровень:** товарная позиция `(order_id, order_item_id)`, затем агрегат по категории.
- **Выручка:** `SUM(price)` позиций заказов со статусом `delivered`; доставка (`freight_value`) не входит. Критерий тот же, что в вопросе 1 и в контроле 13 221 498.11.
- **Категория:** `COALESCE(перевод, исходное название, 'UNKNOWN')`. Все соединения с `products` и переводами — `LEFT JOIN`, поэтому товары без категории и без перевода не пропадают.
- **Знаменатель доли:** общая выручка по тем же позициям (оконная `SUM() OVER ()`), а не сумма уже отобранных групп.
- **Деньги:** `numeric`, без `float`. Доли округлены до 0.01, сумма округлённых долей = 99.96 % (эффект округления 74 значений, не потеря денег; сумма самих выручек сходится копейка в копейку).

## Что сознательно не делали

- Не сливали непереведённые категории в `UNKNOWN`: это скрыло бы 5 240.58 реальной выручки двух категорий.
- Не считали категорию через `payments`: сумма платежей — не выручка товара (см. контракт).
- «Категория заказа» не вводилась: заказ может содержать товары разных категорий, поэтому по категориям складывается только выручка позиций, но **не число заказов** (сумма заказов по категориям 97 276 против 96 478 delivered-заказов с позициями).
