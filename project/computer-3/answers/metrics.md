# Определения известных метрик

Эти определения воспроизводят опубликованные контрольные значения исходного снимка; после вброса и согласования с владельцами ответов их нужно пересмотреть. Во всех ответах источник — `core`/`mart`, без прямого чтения `raw`. Денежные значения — `numeric`, округление выполняется после агрегации; валюту исходные данные явно не задают.

| Вопрос | Определение, уровень и ограничения |
|---|---|
| 1 | Выручка — сумма `order_items.price` заказов со статусом `delivered`, без доставки и платежей. Месяц — `orders.order_purchase_timestamp`, от 2016-09-01 включительно до 2018-09-01 исключительно; календарь обеспечивает все 24 месяца. Число заказов — уникальные `order_id` всех статусов в этом периоде. Это выбранное командой определение числа оформленных заказов, а не подтверждённое организаторами требование; статус выручки отличается намеренно. Отсутствующая дата оформления не попадает в месяц, её нужно отдельно диагностировать. Контроль 13 221 498.11 применим к указанному периоду исходного снимка. |
| 2 | Топ продавцов — сумма цены **их собственных** позиций в `delivered` за весь снимок; заказ может учитываться у нескольких продавцов. Число заказов — `count(distinct order_id)` в разрезе продавца, единицы — число строк позиций. Без фильтра даты, доставка и платежи не входят. |
| 3 | Чек заказа — сумма `price + freight_value` его позиций, затем среднее по всем заказам `delivered` за весь снимок. Заказ без позиций получает 0 и остаётся в знаменателе; это допущение нужно пересмотреть, если такие заказы обнаружатся. Позиция по контракту представляет одну единицу, поэтому среднее число строк и единиц одинаково. |
| 4 | Покупатель — `customer_unique_id`, а не `customer_id`; повторный — более одного отдельного заказа на человека за весь снимок, независимо от статуса. Доля = число повторных / число покупателей × 100. Это согласованное для контрольного расчёта определение повторных оформлений, включая недоставленные или отменённые заказы, не подтверждённая метрика завершённых покупок. Результат исходного снимка — 96 096 и 3,12%; при ином бизнес-определении пересчитать. |
| 5 | Выручка категории — та же товарная цена `delivered`, что в вопросе 2, за весь снимок. Доля = выручка категории / общая товарная выручка × 100. Группировать по исходной категории; отсутствующая категория — отдельная группа, отсутствие перевода не означает отсутствие категории. Проверить сумму всех групп, включая неизвестную. |

Для вопросов 2–3 дату вручения не используют: даже `delivered` может не иметь её; дата оформления также не ограничивает выборку. `NULL` в цене или доставке не приравнивается к нулю: соответствующий чек/выручка неизвестен. Окончательное сравнение с другими ролями ожидает их SQL и фактические результаты. Не суммируйте число заказов продавцов: один заказ может содержать товары нескольких продавцов; не соединяйте позиции с платежами и отзывами без предварительной агрегации.
