# Компьютер 4 — сохранность особенностей данных

Проверка того, что особенности исходной выгрузки из `qa/README.md` не потеряны при переносе `raw` → `core` и обрабатываются осознанно. Особенности **не считаются ошибками** автоматически: PASS — число совпало и условие выполнено; WARN — особенность сохранена, объяснена, и её нужно помнить при расчётах; FAIL — потеря данных.

## Как запустить

С поднятой базой и собранным `core`, из `project/`:

```bash
docker compose exec -T postgres psql -X -U hack -d marketplace -v ON_ERROR_STOP=1 --csv \
  < quality/computer-4/01_feature_preservation.sql
docker compose exec -T postgres psql -X -U hack -d marketplace -v ON_ERROR_STOP=1 --csv \
  < quality/computer-4/02_q5_raw_vs_core.sql
```

Скрипты работают в `READ ONLY` транзакции и ничего не меняют. Код выхода 0 означает, что SQL выполнился; статусы нужно прочитать в выводе. Не запускайте `--reset`.

## Ограничения

- Проверено на снимке исходной выгрузки; ожидаемые числа (610, 13, 775, 1, 8, 547, 814) относятся к нему и после вброса требуют пересчёта: скрипт покажет FAIL при расхождении с ними — это сигнал пересчитать ожидания, а не обязательно ошибка модели.
- Запуск через Docker не выполнялся (Docker в среде проверки не работал); использовался локальный PostgreSQL 16.
- Сверка raw/core по финансам на уровне заказов и продавцов — задача компьютера 3; ключи и связи — компьютера 2. Здесь они не дублируются.
- Часовые пояса и историчность источник не содержит и не проверялись.
